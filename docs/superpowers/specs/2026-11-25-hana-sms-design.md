# 하나카드 문자(SMS) 자동 등록과 받은 경로 표시 (짧은 설계)

## 왜

하나카드 결제 중 문자로만 오는 것(예: 자동납부)이 자동 등록되지 않고 알림함에 남는다. 2026-11-24에 온 `하나0*8*승인 김*수님 SK브로드밴드-자동납 26,950원 11/23 정상처리`가 그렇게 빠져 80만원 구간 달성이 안 보였다. 또 자동 등록된 결제가 어느 경로(문자/푸시)로 들어왔는지 보고 싶다.

## 목표

- 하나카드 승인 문자(위 형식)를 결제로 자동 등록한다.
  - 날짜는 문자에 적힌 날(MM/DD), 시각은 **문자를 받은 시각**(사용자 지정). 연도는 기존 규칙(12/31 문자를 1/1에 받으면 작년).
  - 문자에 적힌 날을 쓰는 이유: 받은 날을 쓰면 월말 결제가 다음 달 실적으로 들어간다.
- 같은 카드·금액·종류·날짜의 결제가 **다른 경로**(문자↔푸시)로 이미 있으면 중복으로 보고 건너뛴다. 같은 경로끼리는 지금처럼 정확한 시각으로만 중복을 판단한다(같은 날 같은 금액 두 번 결제는 둘 다 들어감).
- 자동 등록 결제의 메타 줄에 경로를 붙인다: `자동(SMS)` / `자동(PUSH)`. 문자 앱에서 온 결제는 SMS, 그 밖(하나카드 앱, 카카오톡 등)은 PUSH. 기존 결제도 저장된 앱 패키지로 바로 표시된다.
- 파서 버전을 올려 알림함에 남은 하나카드 문자가 앱 시작 때 다시 검사되어 등록된다. 같은 날짜의 직접 입력 결제가 있으면 지금 규칙대로 합쳐진다.

## 하지 않는 것

- 취소·할부·해외 문자 형식(샘플 없음). 다른 형식은 지금처럼 알림함에 남는다.
- `[하나카드] 승인 안내 ◆ 사용금액…` 형식.
- 문자 행을 나중에 온 푸시의 정확한 시각·누적금액으로 고쳐 쓰기(먼저 들어온 쪽을 유지).
- DB 변경(경로는 기존 `sourcePackage`로 판단).

## 접근

- **선택:** 하나카드 문자 전용 파서 추가 + Ingestor 저장 단계에 '다른 경로 같은 날' 중복 검사 + 패키지로 경로를 판단하는 함수 하나를 UI와 Ingestor가 함께 쓴다.
- 제외: 거래에 경로 열을 추가(DB 마이그레이션) — `sourcePackage`가 이미 같은 정보를 담고 있어 불필요.

## 알고 있는 위험

- 샘플이 한 건이라 형식 변형(가맹점 공백, 끝 문구)이 다르면 알림함에 남는다(등록 누락이지 오등록은 아님).
- 같은 날 같은 금액 결제 두 건 중 한 건이 푸시로만, 다른 한 건이 문자로만 오면 문자 쪽이 중복으로 빠진다(둘 다 받는 사용자에게는 드묾).
- 문자 알림이 대화형(MessagingStyle)이 아니고 다시 올라오며 받은 시각이 바뀌면 같은 문자가 두 번 들어갈 수 있다.

## 빌더 재량

- 문자 정규식의 세부(앞의 `[Web발신]`, 줄바꿈 처리), 문자 앱 패키지 목록, 파일 배치, 테스트 구성.
