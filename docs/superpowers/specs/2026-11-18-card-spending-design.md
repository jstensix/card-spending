# CardSpending 설계 문서

작성일: 2026-11-18
상태: 승인됨 (2026-11-18)

## 1. 의도와 이유

사용자는 신용카드를 여러 장 쓴다. 지금은 카드마다 카드사 앱에 들어가서 이번 달 실적을 확인해야 하는데, 이게 너무 불편하다. 그래서 카드 결제 알림을 자동으로 읽어서, **모든 카드의 해당 월 결제 금액과 실적인정 금액을 한 화면에서 보여주는** 앱을 만든다.

본인 한 명만 쓰는 개인용 앱이다. Play 스토어에 올리지 않고, Android Studio로 본인 폰에 직접 설치한다.

판단 기준: **"카드사 앱을 열지 않고도 이번 달 실적을 믿고 볼 수 있는가."**

## 2. 목표, 비목표, 반목표

### 목표
- 카드 결제 알림(카카오톡 알림톡, 카드사 앱 푸시)을 자동으로 읽어서 결제를 기록한다.
- 메인 화면에서 카드별 **해당 월 결제 금액**과 **실적인정 금액**을 보여준다.
- 실적 미인정 항목은 코드에 고정된 목록에서 카드별로 골라 지정한다.
- 결제 건마다 인정/미인정을 직접 바꿀 수 있다.
- 결제를 직접 추가할 수 있다. 설치 전 결제와 놓친 알림을 채우기 위한 기능이다.
- 같은 결제가 여러 경로로 와도 한 번만 기록한다.
- 카드사 로고를 보여준다.
- 앱 안에서 연결한 구글 계정의 드라이브에 데이터를 자동으로 백업하고, 새 폰이나 재설치한 앱에서 복원한다.

### 비목표 (이번 버전에서 하지 않음)
- 롯데카드, 하나카드 외의 카드사
- 문자(SMS) 수신
- 자체 서버, 여러 기기 사이의 실시간 동기화
- 카드 이미지 (BIN 기반 자동 조회 또는 직접 선택). 사용자가 로고만으로 충분하다고 결정했다.
- 목표 실적(예: 전월실적 30만 원) 대비 진행률, 혜택 한도 추적, 통계/차트, 예산 기능
- 미인정 항목을 앱 안에서 추가하거나 편집하는 기능. 항목은 코드에 고정한다.

### 반목표 (기술적으로는 돌아가더라도 실패로 보는 것)
- **결제가 흔적 없이 빠지는 것.** 카드 알림으로 보이는데 읽지 못한 알림은 반드시 '인식 실패' 목록에 원문 그대로 남겨야 한다.
- **같은 결제가 두 번 집계되는 것.**
- **결제와 관계없는 알림을 저장하는 것.** 특히 개인 카카오톡 대화 같은 알림은 저장하면 안 된다. 앱은 모든 알림을 받지만, 카드 결제 알림이나 그 후보만 저장한다.
- 전체 카드번호를 저장하는 것. 끝 4자리만 저장한다.
- 결제 데이터를 외부 서버로 보내는 것. 단, 사용자 본인 구글 드라이브의 앱 전용 폴더로 보내는 백업은 사용자가 허용했다(5.10).

## 3. 제약

- **기존 프로젝트:** `C:\dev\CardSpending`, 패키지 `com.jstensix.cardspending`. AGP 9.4.1(Kotlin 내장), compileSdk/targetSdk 37, minSdk 31, Java 11 호환. 아직 Activity와 화면이 없다. 의존성은 appcompat, material(View 기반)만 있다.
- **카드사:** 롯데카드, 하나카드만 지원한다.
- **알림 경로:** 롯데는 카카오톡 알림톡으로 온다. 하나는 하나카드 앱 푸시로 오고, 카카오톡 알림톡으로도 올 수 있으며, 둘 다 올 수도 있다.
- **알림 속 카드번호는 일부가 가려져 있다.** 두 카드사 모두 끝 4자리 중 **1번째와 3번째 숫자만 보이고**, 2번째와 4번째는 `*`로 가려진다. 예: 롯데 `7*1*`, 하나 `0*8*`.
- **알림 문구에는 연도가 없다.** 예: `11/18 11:43`, `11.18 17:29`.
- **알림 문구에는 업종이 없고 가맹점명만 있다.** 그래서 미인정 판정은 가맹점명 키워드와 결제 유형(할부)으로만 할 수 있다.
- **알림은 '승인' 기준이다.** 카드사 공식 실적은 매입 기준이고 카드사마다 제외 규칙이 있어서, 앱의 숫자와 차이가 날 수 있다. 이 앱의 숫자는 추정치다.

## 4. 접근법 (검토한 방법과 선택)

### 4.1 알림을 읽는 방법
| 방법 | 판단 |
|---|---|
| **알림 리스너 (NotificationListenerService)** | **선택.** 카카오톡 알림톡과 카드사 앱 푸시를 모두 받을 수 있는 유일한 방법이다. |
| 문자 수신 (SMS BroadcastReceiver) | 제외. 롯데 알림이 문자가 아니라 카카오톡으로 온다. |
| 화면 읽기 (접근성 서비스) | 제외. 카톡 화면이 열려 있을 때만 읽혀서 불안정하고, 필요한 권한이 훨씬 넓다. |
| 카드사 데이터 연동 (마이데이터, 스크래핑) | 제외. 개인이 쓸 수 있는 공개 API가 없다. |

저장은 폰 안의 로컬 DB(Room)를 쓰고, 화면은 Jetpack Compose로 만든다. 프로젝트에 화면이 하나도 없어서 Compose로 시작하는 게 가장 간단하다.

### 4.2 실적 미인정 판정
1. 키워드 규칙만 쓰는 방법: 완전히 자동이지만, 가맹점명이 예상과 다르게 찍히면 놓친다.
2. **키워드 규칙과 결제 건별 직접 수정을 함께 쓰는 방법:** **사용자가 선택했다.** 이후 사용자가 "규칙 항목은 코드에 고정하고, 카드별로 항목을 골라 지정한다"로 구체화했다.

### 4.3 앱 설치 전 결제와 놓친 결제
1. 알림으로 들어온 것만 집계하는 방법: 첫 달과 놓친 결제가 실제보다 적게 나온다.
2. **결제를 직접 추가하는 방법:** **사용자가 선택했다.**

### 4.4 카드 시각 표시
1. BIN 기반으로 카드 이미지를 자동 조회하는 방법: 공개된 BIN-이미지 목록이 없고, 전체 카드번호를 저장해야 해서 제외했다.
2. 카드마다 이미지를 직접 고르는 방법: 사용자가 필요 없다고 했다.
3. **카드사 로고만 보여주는 방법:** **사용자가 선택했다.**

### 4.5 백업
1. Android 자동 백업(폰의 구글 백업): 앱이 할 일은 거의 없다. 하지만 앱 서명 키가 같아야 복원되는데, Android Studio 기본 디버그 키는 PC마다 다르다. 사용자는 서명 키를 관리하고 싶지 않다고 했다.
2. **앱에서 구글 로그인 후 드라이브 앱 전용 폴더에 자동 백업:** **사용자가 선택했다.** 서명 키와 관계없이 복원된다. 대신 Google Cloud 콘솔에서 처음 한 번 설정해야 한다.
3. 백업 파일 내보내기/가져오기: 설정이 필요 없다. 하지만 사용자가 직접 눌러야 하고, 마지막으로 내보낸 뒤의 데이터는 복원되지 않는다.

## 5. 사용자가 정한 것

### 5.1 메인 화면
카드마다 해당 월의 결제 금액과 실적인정 금액을 보여준다. 위쪽에서 월을 넘길 수 있다(◀ ▶).

```
┌ 2026년 11월 ──────── ◀ ▶ ┐
│ [로고] 롯데 텔로 (7*1*)    │
│   결제      523,400원      │
│   실적인정  481,200원      │
│ ────────────────────────── │
│ [로고] 하나 생활 (0*8*)    │
│   결제      120,000원      │
│   실적인정  120,000원      │
└────────────────────────────┘
```

### 5.2 카드 등록
- 카드사(롯데, 하나), **끝 4자리**, 별칭을 사용자가 입력한다.
- 그 카드에 적용할 미인정 항목을 체크한다(5.5).

### 5.3 알림 형식 (실제 샘플)

**롯데카드 (카카오톡 알림톡):**
```
세븐일레븐 판교LH테크노점
11,000원 승인
김수 텔로 SE(7*1*)
일시불, 11/18 11:43
누적금액 3,220,782원

채널 추가하고 이 채널의 마케팅 메시지 등을 카카오톡으로 받기
```
- 1줄: 가맹점명
- 2줄: `{금액}원 승인`
- 3줄: `{가려진 이름} {카드 상품명}({가려진 끝 4자리})`
- 4줄: `{일시불|할부 정보}, {MM/DD HH:mm}`
- 5줄: `누적금액 {금액}원`
- 마지막 안내 문구는 무시한다.
- 참고: 처음 받은 샘플에는 `(71*)`로 보였지만, 사용자가 실제 형식은 `7*1*`이라고 확인했다.

**하나카드 (하나카드 앱 푸시):**
- 제목: `(결제) 9,900원`
- 본문: `거궁찬판교점 / 신용(일시불,0*8*) / 11.18 17:29 / 누적이용금액 532,231원`
- 사용자가 본문을 한 줄로 옮겨줬기 때문에, 실제 구분자가 줄바꿈인지 ` / `인지는 확인하지 못했다. 파서는 **둘 다 받아들여야 한다.**

**하나카드 (카카오톡 알림톡):** 형식을 아직 모른다. 샘플을 받기 전까지는 인식 실패 목록으로 보낸다.

### 5.4 알림 판별과 파싱
- **알림을 보낸 앱의 패키지명에 의존하지 않는다.** 모든 알림을 받아서 문구 형식으로 롯데인지 하나인지 판별한다. 알림이 오는 앱이 바뀌어도 동작하게 하려는 것이다.
- 제목, 본문, 펼친 본문(BIG_TEXT), 메시지 목록(카카오톡 MessagingStyle)을 모두 살펴봐야 한다. 카카오톡은 같은 채널의 메시지를 묶어서 알림을 다시 올리기 때문에, 같은 결제가 여러 번 들어올 수 있다. 이 경우는 중복 제거(5.7)로 처리한다.
- 결제마다 원본 알림 문구와 보낸 앱의 패키지명을 함께 저장한다. 문제가 생겼을 때 확인하기 위해서다.

### 5.5 실적 미인정 항목
항목은 코드에 고정하고, 카드마다 해당하는 항목을 체크한다. 초기 목록은 다음과 같다(사용자가 검토 단계에서 반대하지 않았다).

| 항목 | 판정 방법 (초기 키워드는 [제안]) |
|---|---|
| 세금 | 가맹점명에 `국세`, `지방세`, `위택스`, `홈택스`, `세무서` |
| 공과금 | 가맹점명에 `한국전력`, `한전`, `도시가스`, `상수도`, `수도요금` |
| 아파트관리비 | 가맹점명에 `관리비`, `관리사무소` |
| 상품권·선불충전 | 가맹점명에 `상품권`, `기프트카드`, `선불` |
| 보험료 | 가맹점명에 `보험`, `생명`, `화재`, `손해` |
| 등록금 | 가맹점명에 `등록금`, `대학교` |
| 할부 결제 | 결제 유형이 할부(일시불이 아님) |

- **결제 건마다 인정/미인정을 직접 지정할 수 있다. 직접 지정한 값이 항목 규칙보다 우선한다.** 나중에 규칙이 바뀌어도 직접 지정한 건은 그대로 유지된다.
- 결제 내역에는 미인정된 이유(어떤 항목 때문인지, 또는 직접 지정했는지)를 보여준다.

### 5.6 결제 직접 추가
- 카드, 금액, 가맹점, 날짜와 시각, 일시불/할부를 입력한다.
- 직접 추가한 건에도 미인정 항목 규칙이 똑같이 적용된다.
- **[제안] 승인/취소 구분:** 취소도 직접 추가할 수 있다. 취소는 원래 결제를 고르고 취소 금액을 입력한다. 부분취소일 수 있으므로 원래 금액보다 작은 값도 넣을 수 있다. 취소 알림 형식을 아직 몰라서, 처음 오는 취소는 대부분 인식 실패로 갈 것이기 때문이다.

### 5.7 중복 제거
같은 결제가 하나카드 앱 푸시와 카카오톡으로 둘 다 올 수 있다. 카카오톡이 알림을 다시 올리는 경우도 있다(5.4). 두 알림이 아래 조건을 모두 만족하면 같은 결제로 보고 **한 건만 저장한다.**

- 카드사, 보이는 카드번호(예: `0*8*`), 금액, 승인/취소 구분, 승인 시각(분 단위)이 모두 같다.
- 누적금액이 같다. 둘 중 하나라도 누적금액이 없으면 이 조건은 건너뛴다.

같은 금액을 1분 안에 실제로 두 번 결제하면 누적금액이 달라지므로 두 건 모두 남는다. 단, 누적금액이 없는 알림끼리 비교할 때는 이런 실제 두 건이 한 건으로 합쳐질 수 있다. 이때는 사용자가 직접 추가로 보완한다.

### 5.8 인식 실패 목록
- 카드 결제 알림처럼 보이지만 읽지 못한 알림은 원문, 받은 시각, 보낸 앱을 그대로 저장해서 목록으로 보여준다.
- 메인 화면에 인식 실패 건수를 표시한다.
- 사용자가 항목을 무시하거나 지울 수 있다.
- **[제안] 직접 등록:** 인식 실패 항목에서 '결제로 등록' 또는 '취소로 등록'을 누르면 원문을 옆에 띄운 채 직접 추가 화면(5.6)이 열린다. 사용자가 저장하면 그 항목은 목록에서 빠진다.
- **[제안] 다시 읽기:** 실패 항목은 제목, 본문, 펼친 본문, 메시지 목록, 받은 시각을 따로 저장한다. 앱을 업데이트해서 파서가 바뀌면 남아 있는 실패 항목을 다시 파싱한다. 이때도 중복 제거(5.7)를 거친다. 새 알림 형식(취소, 하나 카톡, 해외 결제)을 나중에 추가해도 이미 쌓인 알림이 자동으로 반영되게 하려는 것이다.

### 5.9 카드사 로고
두 카드사 공식 홈페이지에서 받은 정사각형 아이콘을 앱 리소스로 넣는다. 개인용으로만 쓴다. 다른 사람에게 배포하면 상표권 문제가 생길 수 있다.

### 5.10 구글 드라이브 백업
- 사용자가 앱 안에서 구글 계정을 연결한다. 폰에 로그인된 계정과 별개로 고를 수 있다.
- 백업은 그 계정 드라이브의 **앱 전용 숨김 폴더**(appDataFolder, `drive.appdata` 권한)에 저장한다. 구글은 이 권한을 '민감하지 않은 권한'으로 분류하기 때문에 앱 심사가 필요 없다.
- **결제 데이터가 바뀔 때마다 자동으로 백업한다**(결제 기록, 직접 추가, 인정/미인정 변경, 카드 설정 변경 등). 네트워크가 없으면 연결될 때까지 미룬다.
- 새 폰이나 재설치한 앱에서 같은 계정을 연결하면 복원할 수 있다. **앱 서명 키가 바뀌어도 복원된다.**
- 백업이 연결되지 않았거나 마지막 백업이 실패했으면 메인 화면에 알린다. 설정 화면에는 마지막 백업 시각과 '지금 백업' 버튼을 둔다.
- **[제안] 복원 방식 (최종 검토 후 수정):** 계정을 연결할 때 드라이브에 백업이 있으면, 폰에 데이터가 있든 없든 **'드라이브 백업으로 복원' / '이 폰의 데이터로 덮어쓰기' / '취소'** 중에서 고르게 한다. 고르기 전에는 연결(자동 백업)이 켜지지 않는다. 드라이브 확인에 실패하면 연결하지 않고 다시 시도하게 한다. 이미 연결된 뒤에는 설정의 '드라이브에서 복원' 버튼으로 복원하고, 현재 데이터를 덮어쓴다고 확인받는다. 처음 제안(데이터가 없을 때만 묻기)은 새 폰에서 카드를 먼저 등록하면 거의 빈 백업이 진짜 백업을 덮어쓰는 문제가 있어서 바꿨다.
- **[제안] 백업 보관:** 최신 백업과 그 직전 백업, 2개를 보관한다. 백업 도중 문제가 생겨도 이전 백업으로 돌아갈 수 있게 하려는 것이다.
- **[제안] Android 자동 백업과의 관계:** 결제 DB는 Android 자동 백업에서 뺀다. 두 백업이 서로 다른 시점의 데이터를 복원해서 충돌하지 않게, 드라이브 백업 하나만 기준으로 삼는다.
- **주의:** Google Cloud의 OAuth 동의 화면이 '테스트' 상태이면 로그인 권한이 7일마다 만료된다. 그래서 '프로덕션'으로 게시해야 한다. 민감하지 않은 권한만 쓰므로 게시할 때 심사가 필요 없다.

## 6. 이 문서에서 정한 것 ([제안], 사용자 확인 전)

- **[제안] 월 기준:** 승인 일시 기준으로 매월 1일부터 말일까지. 대부분 카드사의 전월실적 기준과 같다.
- **[제안] 연도 추론:** 알림을 받은 시각(postTime)의 연도를 쓴다. 단, 문구 속 월이 받은 시각의 월보다 크면(예: 12/31 결제 알림을 1/1에 받은 경우) 전년도로 본다.
- **[제안] 금액 계산:**
  - 결제 금액 = 해당 월 승인 합계 − 해당 월 취소 합계
  - 실적인정 금액 = 결제 금액 중 인정된 건만 같은 방식으로 계산한 값
- **[제안] 취소 처리:**
  - 취소 알림 샘플이 아직 없다. 그래서 '취소'가 들어간 알림을 취소로 추정해서 파싱하고, 파싱하지 못하면 인식 실패로 보낸다.
  - 취소가 오면 원래 결제(같은 카드, 금액이 취소 금액 이상, 가맹점명이 같으면 우선, 가장 최근 승인)를 찾아 연결한다. 부분취소도 연결되게 하려는 것이다. 취소 건은 원래 결제의 인정/미인정 상태를 따른다. 미인정 결제를 취소하면 결제 금액만 줄고 실적인정 금액은 그대로다.
  - 취소 금액은 **취소된 달**에서 뺀다. 카드사 대부분의 방식이라고 판단했지만, 카드사별로 다를 수 있다.
- **[제안] 할부:** 승인 금액 전체를 승인한 달에 넣는다.
- **[제안] 카드 연결:** 결제에는 카드사와 보이는 카드번호(예: `7*1*`)를 저장하고, 등록된 카드와는 화면에 보여줄 때 매칭한다. 그래서 카드를 나중에 등록해도 이전 결제가 자동으로 그 카드에 붙는다.
- **[제안] 미등록 카드:** 등록된 카드와 매칭되지 않는 결제는 '미등록 카드 결제'로 메인 화면에 건수를 표시한다.
- **번호 충돌 (사용자 확인):** 사용자는 같은 카드사에 1·3번째 숫자가 같은 카드를 갖고 있지 않다. 그래서 그런 카드를 등록하려고 하면 "알림으로 서로 구분할 수 없다"고 경고만 한다.
- **[제안] 미인정 판정 시점:** 저장할 때 판정하지 않고, 화면에 보여줄 때마다 현재 규칙으로 판정한다. 그래서 규칙을 바꾸면 지난 결제에도 바로 반영된다(직접 지정한 건은 제외).
- **[제안] 권한 안내:** 앱을 열었을 때 알림 접근 권한이 꺼져 있으면 경고하고 설정 화면으로 보낸다. 배터리 최적화 제외도 안내한다.

## 7. 화면 구성

1. **메인:** 월 선택, 카드 목록(로고, 별칭, 보이는 카드번호, 결제 금액, 실적인정 금액), 경고 배너(알림 권한 꺼짐, 인식 실패 N건, 미등록 카드 결제 N건)
2. **카드 결제 내역:** 해당 월 결제 목록(날짜, 가맹점, 금액, 인정/미인정과 그 이유). 건별 인정/미인정 변경, 직접 추가 버튼, 건 삭제
3. **카드 관리:** 카드 추가, 수정, 삭제(카드사, 끝 4자리, 별칭, 미인정 항목 체크)
4. **결제 직접 추가**
5. **인식 실패 목록**
6. **권한 안내**
7. **설정:** 구글 계정 연결과 해제, 마지막 백업 시각, '지금 백업', '드라이브에서 복원'

## 8. 설치와 기기 설정 (사용자가 직접 할 일)

- Android Studio로 설치한다. APK 파일로 직접 설치하면 Android 13 이상에서 '제한된 설정 허용'을 켜야 알림 접근 권한을 줄 수 있다.
- 설정에서 이 앱의 **알림 접근 권한**을 허용한다.
- 이 앱을 **배터리 최적화 대상에서 뺀다.** 삼성 같은 일부 폰은 배터리 절약 기능 때문에 알림 리스너가 멈출 수 있다.
- **카카오톡:** 알림과 미리보기를 켠다. 'PC 버전 사용 중 모바일 알림 끄기' 같은 옵션이 켜져 있으면 결제를 놓친다.
- **하나카드 앱:** 결제 푸시 알림을 켠다.
- **Google Cloud 처음 설정 (한 번만):** 프로젝트를 만들고 Drive API를 켠다. OAuth 동의 화면을 만들어 '프로덕션'으로 게시한다. 마지막으로 Android OAuth 클라이언트를 만들고 패키지명과 PC의 디버그 키 지문(SHA-1)을 등록한다. 구현 계획에 단계별 안내를 넣는다.
- **PC를 바꾸거나 Android Studio를 다시 설치했을 때:** 디버그 키가 바뀌므로 새 SHA-1을 Android OAuth 클라이언트로 하나 더 등록한다. 서명 키가 바뀌면 기존 앱을 지우고 다시 설치해야 할 수 있다. 다시 설치한 뒤 같은 구글 계정을 연결하면 드라이브에서 복원된다.
