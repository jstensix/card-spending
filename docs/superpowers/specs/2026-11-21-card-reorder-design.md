# 카드 탭에서 길게 눌러 카드 순서 바꾸기 (짧은 설계)

## 왜

카드는 등록한 순서(id 순)로 고정돼 있다. 사용자는 자주 보는 카드를 위로 올리는 등 원하는 순서로 보고 싶다.

## 목표

- 카드 탭에서 카드를 **길게 누르면** 진동과 함께 살짝 떠오르고, 그대로 위아래로 끌어 놓아 순서를 바꾼다(사용자가 고른 A 방식: 편집 모드 없음).
- 놓는 순간 한 번만 저장한다(끄는 도중에는 저장하지 않음).
- 짧게 누르면 지금처럼 카드 편집 화면이 열린다.
- 정한 순서는 카드 목록을 쓰는 모든 곳에 적용된다: 카드 탭, 홈 카드 목록, 결제 직접 입력의 카드 선택.
- 새 카드는 맨 아래에 붙는다. 카드를 수정해도 자리는 그대로다.
- 순서는 백업에 포함된다. 순서가 없는 예전 백업은 등록 순서로 복원된다.

## 하지 않는 것

- 홈 화면에서 끌기.
- 화면 낭독(TalkBack) 사용자용 대체 조작.

## 반실패(이러면 실패)

- 업데이트 직후 기존 카드 순서가 바뀜.
- 카드를 수정·저장하면 그 카드가 맨 위(또는 다른 자리)로 튐.
- 짧게 누르기(편집 열기)가 끌기와 충돌해 안 됨.

## 접근

| 방법 | 장단 |
|---|---|
| **라이브러리 `sh.calvin.reorderable:reorderable` 3.1.0 (선택)** | 떠오르는 효과·자동 스크롤·LazyColumn 안 항목 이동을 이미 처리. 의존성 하나 추가. 2026-04 출시. |
| 직접 구현(`detectDragGesturesAfterLongPress` + 자리 바꾸기) | 의존성 없음. 스크롤 목록 안에서 끄는 동작을 직접 맞춰야 해 오류 여지가 큼. |

편집 모드 + ↑↓ 버튼(B 방식)은 사용자가 A를 골라 제외.

사용자가 방법은 맡김: 라이브러리는 Claude의 선택.

## 결정

- `Card`에 `sortOrder: Int` 추가, DB 버전 2→3. 마이그레이션은 기존 행을 `sortOrder = id`로 채워 지금 순서를 유지한다.
- 카드 조회는 `ORDER BY sortOrder, id`.
- 순서 유지 규칙은 저장소(`saveCard`)가 맡는다: 새 카드는 현재 최댓값+1, 기존 카드는 저장된 `sortOrder`를 그대로 쓴다(편집 화면은 순서를 모름).
- 순서 저장은 저장소의 한 함수가 id 목록을 받아 한 트랜잭션으로 0..n-1을 매기고, 다른 쓰기처럼 백업 변경 알림을 부른다.
- 백업은 `Card` 직렬화에 새 필드(기본값 있음)가 따라가 예전 백업도 읽힌다.

## 빌더 재량

- 떠오른 카드의 모양(그림자·크기), 진동 종류.
- 끄는 동안 화면에 들고 있는 임시 목록의 관리 방법(저장 후 DB 흐름이 다시 내려올 때 깜빡이지 않게).
- 테스트 구성, 마이그레이션 테스트 방식(기존 MigrationTest 패턴 재사용).
