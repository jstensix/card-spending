# 알림함에 넣을 알림을 등록 카드 번호로 판단 (짧은 설계)

## 왜

알림함('읽지 못한 카드 알림')에 결제와 무관한 알림이 쌓인다: 본문에 '롯데카드'를 언급한 쇼핑 앱 메시지, 하나카드 앱의 `(광고)` 알림, 결제예정금액 안내. 지금 규칙은 메신저가 아닌 앱이면 본문에 카드사 이름만 있어도 넣기 때문이다.

## 목표

- 파서가 이해하지 못한 알림은 **등록한 카드의 마스킹 번호**(예: `7*1*`, `0*8*`) 또는 **등록한 카드의 실제 끝 4자리**(앞뒤가 숫자가 아닌 4자리, 예: `7419`)가 제목·본문에 있을 때만 알림함에 넣는다.
- 메신저(카카오톡 등)와 대화형 알림은 지금처럼 제목(보낸 사람)이 '롯데카드'/'하나카드'여야 하고, 거기에 더해 위 번호가 있어야 한다.
- 이미 쌓인 알림함 항목을 새 규칙으로 다시 검사해 해당하지 않는 항목은 지운다.

## 하지 않는 것

- 롯데/하나 결제 알림 파서(이미 인식되는 형식)는 바꾸지 않는다. 인식된 결제는 지금처럼 저장된다.
- 카드사 이름만 있는 알림, '알려진 앱 + 금액 + 결제 단어' 규칙은 없앤다.

## 결정

- 사용자가 승인한 규칙 그대로. 접근은 하나뿐이다: 판단 함수에 등록 카드 목록을 넘긴다(알림 수신 시점의 카드 기준).
- 파서 버전을 올려(1→2) 앱 시작 시 기존 알림함 항목을 다시 검사한다. 새 규칙에서 무시 대상이면 **삭제**, 결제로 인식되면 지금처럼 저장 후 숨김, 여전히 후보면 남긴다.

## 알고 있는 위험

- 카드사가 결제 알림에서 번호를 빼면 그 알림은 알림함에도 남지 않는다(사용자에게 고지함).
- 등록 카드가 하나도 없을 때 앱이 시작되면 알림함 항목이 모두 지워진다(번호를 비교할 카드가 없음). 카드를 등록하지 않은 상태는 이 앱에서 드문 경우라 받아들인다.

## 빌더 재량

- 끝 4자리 일치의 숫자 경계 처리, 테스트 구성, 쓰지 않게 되는 '알려진 앱' 조회 코드 정리.
