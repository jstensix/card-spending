# 직접 입력한 결제 수정 + 등록 방식 표시 (짧은 설계)

## 왜

직접 입력할 때 금액, 가맹점, 날짜 등을 잘못 넣는 경우가 있어서, 지우고 다시 넣지 않고 고칠 수 있어야 한다.
목록에서 어떤 결제가 알림으로 자동 등록됐고 어떤 결제를 직접 입력했는지도 한눈에 보여야 한다.

## 목표

- 직접 입력한 결제(`source = MANUAL`)를 수정할 수 있다. 수정 가능한 항목: 카드, 결제/취소, 금액, 가맹점, 날짜, 시간, 일시불/할부, (취소일 때) 원 결제.
- 카드 상세의 결제 줄과 결제 시트에 등록 방식을 표시한다: 알림이면 `자동`, 직접 입력이면 `직접 입력`.

## 하지 않는 것

- 알림으로 들어온 결제(`source = NOTIFICATION`)의 수정. 카드사가 보낸 값이라 틀릴 일이 드물고, 고치면 같은 알림이 다시 왔을 때 중복 판정(카드·금액·시각 비교)이 깨진다. 알림 결제는 지금처럼 인정/미인정 지정과 삭제만 된다.
- 수정 이력 보관, '수정됨' 표시.

## 접근 방식

| 방식 | 장단점 | 결정 |
|------|--------|------|
| 1. 기존 '직접 입력' 화면을 수정 모드로 재사용 | 입력 항목·검사·원 결제 선택이 새 입력과 같다. 화면 이동 1번. | **선택** (사용자) |
| 2. 결제 시트 안에서 바로 수정 | 화면 이동이 없지만 시트가 좁고 입력 로직이 두 곳으로 나뉜다. | 제외 |

## 동작

- **진입:** 결제 시트에 `수정` 버튼. 직접 입력한 결제에만 보인다. 누르면 시트를 닫고 입력 화면을 수정 모드로 연다(경로 `EntryRoute`에 `txId` 추가, 0이면 새 입력).
- **미리 채우기:** 저장된 값으로 모든 항목을 채운다. 카드는 결제의 카드사+마스크와 일치하는 등록 카드로 찾는다. 카드가 삭제돼 없으면 비워 두고 사용자가 고른다.
- **화면 제목:** 수정 모드는 `결제 수정`.
- **저장:** 같은 행을 갱신한다. id, `createdAt`, 인정/미인정 직접 지정(`manualRecognition`)은 유지한다. 결제→취소로 바꾸면 원 결제 선택이 적용되고, 취소→결제로 바꾸면 원 결제 연결을 지운다.
- **원 결제 후보:** 수정 중인 결제 자신은 후보에서 뺀다.
- **중복 경고:** 새 입력과 같은 규칙(같은 날 같은 금액의 알림 결제가 있으면 경고)을 그대로 쓴다.
- **보호:** 수정 대상이 알림 결제면 저장을 거부한다(버튼이 안 보이지만 경로로 직접 들어오는 경우 대비).
- **등록 방식 표시:** 결제 줄과 시트의 보조 문구(`14:32 · 일시불 · 직접 입력`)에 붙인다. 직접 입력 후 알림이 와서 합쳐진 결제는 값이 알림에서 왔으므로 `자동`.

## 빌더 재량

- 수정 모드 로딩 중 표시 방식, 테스트 구성.
- 수정된 결제를 원 결제로 가진 취소 건은 연결을 그대로 둔다(금액을 줄여도 취소 연결을 끊지 않는다).
